## Module Hierarchy

```
top_ti  (rtl/top.sv)
├── conv_interface_ti  (rtl/interface_ti.sv)
│   ├── sram_sp        (rtl/sram_sp.sv)      9 × 16-bit BF16 persistent weight SRAM
│   └── grad_core      (rtl/grad_core.sv)    FP32 gradient computation (backward pass)
└── compute_core_ti    (rtl/compute_core_ti.sv)  BF16 dot-product MAC array (forward pass)
```

No glue logic between interface and compute core — `conv_interface_ti` drives `core_*` signals directly into `compute_core_ti` through named wires in `top.sv`.

## Register Map (AXI4-Lite, 6-bit address)

| Address | Register  | Dir | Description |
|---------|-----------|-----|-------------|
| `0x00`  | CTRL      | W   | [0] start, [1] load_weights, [2] backward |
| `0x04`  | STATUS    | R   | [0] done, [1] busy, [2] wt_loaded, [3] grad_done |
| `0x08`  | TILE_LEN  | RW  | [7:0] tile length |
| `0x0C`  | RESULT    | R   | FP32 forward dot-product result |
| `0x10`  | GRAD_IN   | RW  | FP32 upstream gradient dL/dy |
| `0x14–0x34` | GRAD_W0–W8 | R | FP32 weight gradients dL/dW[0..8] |

AXI4-Stream (512-bit tdata): one beat carries 9 BF16 values at `tdata[16*i+15 : 16*i]` for `i = 0..8`.

## Reproduce the Co-Simulation

### cocotb end-to-end co-simulation (primary M3 deliverable)

Dependencies: Python 3.11.9, cocotb 2.0.1, Icarus Verilog 11.0.

Run from the `m3/` directory:

```bash
python sim/run_ti.py
```

Expected output (last lines):
```
PASS -- all 4 tests passed.
TESTS=3 PASS=3 FAIL=0 SKIP=0
```

Tests run:
- `test_bf16_forward` — T1–T4: ramp weights × unit IFMs, alternating-sign, max BF16, Laplacian kernel
- `test_weight_reuse` — load weights once, compute 4 IFM tiles without reloading
- `test_grad_w` — B1–B4: verify dL/dW = dL/dy × BF16(x[i]) for 4 input vectors

### Standalone VCD testbench (GTKWave)

Requires: Icarus Verilog 11.0, GTKWave.

```bash
# From the m3/ directory
iverilog -g2012 -o sim/tb_top.vvp \
    tb/tb_top.sv \
    rtl/sram_sp.sv rtl/grad_core.sv rtl/interface_ti.sv \
    rtl/compute_core_ti.sv rtl/top.sv

vvp sim/tb_top.vvp
# Expected: PASS — 45.0 (0x42340000) matches expected

gtkwave sim/dump.vcd sim/dump.gtkw
```

The `.gtkw` save file pre-loads three annotated regions:
- **Region 1**: Host Write — AXI4-Lite CTRL write + AXI4-Stream weight beat
- **Region 2**: Compute — start → 11-cycle sequencer → STATUS[0]=done
- **Region 3**: Host Read — AXI4-Lite RESULT readback (FP32 = 0x42340000 = 45.0)

## Reproduce the Synthesis

**OpenLane version:** 2.3.10  
**Release:** `openlane2` PyPI package, version 2.3.10  
**Configuration file:** `synth/config.json`  
**PDK:** sky130A (`sky130_fd_sc_hd`)

### Environment setup

```bash
pip install openlane==2.3.10
```

Required environment variables (set by OpenLane installer):
```
PDK_ROOT=<path to sky130A PDK>
```

### Run synthesis

From the `m3/` directory:

```bash
python -m openlane synth/config.json
```

The completed run is archived at `openlane/runs/RUN_2026-05-21_22-27-19/`. The full console output is committed at `synth/openlane_run.log` (78 steps, all passed). Reports are committed in `synth/` and do not require re-running OpenLane to read.

**Key result:** TT corner WNS = +29.9 ns (PASS), SS corner WNS = −63.0 ns (expected violation at 130 nm for this FP32 datapath depth). See `synthesis_notes.md` for full narrative.
